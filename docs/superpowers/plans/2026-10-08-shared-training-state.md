# 跨进程训练状态与排他运行

问题：CLI 的训练状态仅在自身内存里，API 无法读取，页面仍可再次启动训练。新实现将状态原子写入 `data/training-runtime/status.json`，使用排他创建的 `writer.lock` 阻止同一项目的多个进程同时训练。训练阶段每局发布一次、评测按进度最多每秒写一次，结束/失败最终发布并释放锁。页面接口读取共享状态，启动冲突返回 409。

不根据超时夺取锁，仍存活的慢评测必须保留。若进程确实退出，读取状态显示失败；残留锁启动时报 `TRAINING_LOCK_STALE`，保守保留待核实后清理，不自动删除未知写入者的锁。

验证：共享状态测试先失败后通过。通过实际 Node 子进程验证活进程排他，以及退出后失败状态/残留锁拒绝重入。206 项后端测试通过；异步闭包带来的 TypeScript curriculum 可空检查已用局部引用修复，最终后端构建通过。
