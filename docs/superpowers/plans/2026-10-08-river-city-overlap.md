# 城址与河岸重叠：诊断记录

浏览器证据：QA 弓兵混编验收局的濮阳在约 28.6 倍时，河流从城池底座下穿过。驻军避水已经独立生效，不能由此推断城池也已避水。

代码路径：HistoricalArena 的 compactGeography 将城市和河线进行相同分段坐标变换；ZoomTerrainMap 的 createTerrainField 使用这些河线雕刻河谷，createBuildingSites 仍以城市中心落模型。gradeSettlements 特意在河岸附近减弱整平，不会把河流填掉。现状没有河线绕城或城市避水布局阶段。

全图只读测量：使用 historicGeography(() => .5)，压缩后以 settlementWidths 和河线点到线段最短距离检查 `distance < width * .71 + .04`，1184 城中有 89 个保守包围范围碰到河岸。这是风险范围计数，不等于 89 个全部穿水。濮阳 id 322：x=1.8009675969240266，z=-1.3165111242861736，宽度=.08538832541102984，河道距离=.01573169232495983。

结论：单独增高模型或底座无法解决交叠。应在共享显示地理层协调河道/城址，避免仅移动三维模型造成远近图标与模型错位。不得修改后端原始郡县坐标、道路拓扑、归属、兵力或行军预算。修复后需检查全部城址、临近城池间距、河线连续性和濮阳实景，而非仅用局部截图宣告完成。

本记录完成根因定位，尚未实施河道或城址偏移。

## 后续实现

riverCityLayout 已在 HistoricalArena 的共享显示地理层接入（紧凑、地理两种布局）。对临河城址搜索半径不超过 .35、步长 .025 的陆地位置，检验模型包围范围、海岸和相邻城址。保留所有非坐标游戏字段；郡治锚点同步更新。政治分区、三维地形、道路、模型和标签使用同一结果，不单独偏移模型。

使用最大常规城池规模 level 3（渲染本身对 level 的规模取 min(3, level)）预留范围，升级、兵力和归属不影响城址。显示布局按原始坐标/城址属性缓存，实时兵力、等级与归属从最新状态合并，不缓存过期游戏数据。

测试先复现濮阳安全间距失败，修复后通过；全图最大规模风险计数为 103 → 5（与前面的当前规模 89 口径不同）。不超过 .35 的位移、原数据不可变、玩法字段保留、郡治点对齐和升级/换主稳定性均有测试。剩余 5 个城址未强行扩大位移或删掉城池；需要继续诊断。新布局的浏览器实景验收尚待执行。
