# 修复兵力拆分/合并的训练奖励偏差

原因：utility 对每座城、每支军队分别 min(troops,80)，120 人单个驻军只计 80；分成驻军 60、行军 60 后计 120，平白增加 0.32 奖励。合并则扣除该值，可能惩罚正常集中兵力。

修复：按所属城池与行军部队的实际存活兵力计值，系数仍为 0.008。城市、建筑、资金与实际胜利奖励不变。不修改玩法中的兵力、军费或战斗结算。新增测试先复现 0.32 差异，再验证拆分守恒以及真实损失 20 人减少 0.16。

验证：pnpm test 232 项通过（API 158、Web 74），pnpm build 成功；原有 chunk 体积警告仍在。

训练对照：上一轮 seed 200 / 16 集 / 480 学习回合 / 240 评估回合已结束且被拒绝（归档 run-1791440141640-200-558.json）。现在使用相同初始 542 集策略、种子与预算重跑，改变奖励计算；逐势力统计的添加只影响输出。此为一次新的对照实验，不是重启未结束进程。需等待新归档，不能把奖励修正直接宣称为胜率提升。

对照已结束：run-1791440658676-200-558.json，候选平均领土 27.875，现有 106.5625；16 席位均存活但没有统一胜利、全部未决。候选再次被拒绝，仍使用 542 集策略。奖励守恒修复消除了确定的计分漏洞，但没有改善这次训练战绩，可能需要更根本的奖励权重与学习结构调整，不能宣称该修复已解决战略集结问题。
